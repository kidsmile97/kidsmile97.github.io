## Flip 动画

Flip不是什么动画技术或者一个动画实现插件依赖包，而是指一种动画实现思路。

- F: First 需要关联动画的元素初始状态
- L: Last 元素的最终状态
- I: Invert 反转，使用 transforms/opacity 对最终状态的元素进行状态反转至初始状态
- P: Play 触发动画

## 代码示例

```js
// 获取元素位置
function getLocation(ele) {
  const rect = ele.getBoundingClientRect();
  return rect.top;
}

// first，获取初始位置
const first = getLocation(element);

// last，移动后获取新位置
ul.insertBefore(element, null);
const last = getLocation(element);

// invert，使用 transform 回到初始位置
element.style.transform = `translateY(${first - last}px)`

// play，增加动画移除 invert 阶段添加的状态，请求动画帧执行
requestAnimationFrame(function() {
  element.style.transition = 'all .6s cubic-bezier(0,0,0.32,1)';
  element.style.removeProperty('transform');
})

// 修改样式的动画需要移除 transition 属性，重新添加计算动画属性，才能在下次动画再生效
element.addEventListener(
  'transitionend', 
  (evt) => evt.target.style.removeProperty('transition')
);
```

```js
// 直接使用 animate API 请求样式变更动画，可以合并 invert 以及之后所有阶段
element.animate([
  { transform: `translateY(${first - last}px)` },
  { transform: 'translateY(0)' }
], {
  duration: 600,
  easing: 'cubic-bezier(0,0,0.32,1)',
});
```

## 代码问题解析

- 为什么使用 requestAnimationFrame 请求动画需要移除 transition 属性，而 animate 不需要

答：这与两个 API 的区别相关。

> requestAnimationFrame 是执行动画帧，也就是说这个方法是用来执行动画的一帧的，是一次性的，它会在一帧之内就触发完成结束，如果要在下次重绘之前继续更新下一帧动画，需要再次调用。而在上述代码示例中，requestAnimationFrame 用来直接设置样式了，希望通过样式触发 transition 的动画而不是自身设计一个动画，那么得后加 transition，这样浏览器在重绘的时候才会重新计算 transition 动画，否则就会因为 requestAnimationFrame 一帧直接闪烁掉动画了。

> animate 是创建一个动画并且运行它，是一个生成完整的 Animation 动画并执行的流程，不需要依赖 transition。

- 元素 insertBefore 插入新位置之后再 invert，会不会造成画面闪烁

答：不会，insertBefore 会触发重排（reflow/relayout）（所以 dom 操作的 API 其实都是一个重函数），所以可以实时拿到元素最新的状态和位置，但是渲染是在 js 线程空闲后发起的，js 空闲时元素已经 invert 完成，所以不会触发闪烁。

- 或许你在写一组元素的 Flip 动画的时候出现了问题？

答：核心关键还是重排重绘的问题，要注意对一组元素生成 flip 动画，如果元素之间会相互影响时（如位置），一定要在所有元素都设置到它该在的状态之后，再去获取每一个元素的 last 状态，因为状态是实时的、实时的、实时的！！！

## something good

- 动画能够对用户交互给予实时的反馈过程，smooth 整个过程，提升整个程序系统给用户的流畅性体验，这也是动画设计越来越重要的原因。

- 反应时间。人类对于操作的反应是存在 100ms 左右的窗口时间，在摩尔定律仍有效的当今，100ms 能够做到的事情太多了，动画一方面除了平滑交互过程，还有延长交互，防止交互瞬息导致用户使用疲惫。

## 注意事项

1. 控制执行时间。FLIP 中，FLI 的时间其实只有 100ms，这也是所有动画生成能够用的时间，超过这个时间，整个程序就会给用户呆住的体验。交互动画就变得无用且累赘。而 FLI 没写好，恰恰会导致反复的重排重绘这种重工程。

2. 小心设计你的动画。为什么 invert 阶段重点声明的是 transform & opacity，因为两者动画执行过程中都不会触发重排重绘，保证动画的性能是一切的前提。

3. 小心形变。transform 很强大，但是由于使用的是 GPU 视觉渲染，变换有可能会导致内容形变（拉伸、压缩、模糊，一如 canvas）。在 FLIP 过程中，处理形变反而可能是最麻烦的。
